# شرح موديول inventory_report_generator

## اسم الموديول والوصف

اسم الموديول هو **inventory_report_generator** وهو موديول لنظام أودو يقوم بإنشاء تقارير مخزون ديناميكية ومتقدمة. يوفر الموديول أربعة أنواع مختلفة من التقارير يمكن للمستخدم اختيارها حسب احتياجه، ويدعم التصدير بصيغتي PDF و XLSX (Excel). يتميز الموديول باستخدام مكون واجهة مستخدم OWL (Odoo Web Library) في الواجهة الأمامية واستخدام استعلامات SQL خام للحصول على أداء عالٍ في استخراج البيانات.

## الاعتماديات (Dependencies)

يعتمد هذا الموديول على موديول واحد فقط:

| الموديول | الغرض |
|----------|-------|
| `stock` | موديول إدارة المخزون الأساسي في أودو |

هذا الاعتماد المحدود يجعل الموديول خفيفاً وسهل التثبيت، ولا يتطلب تثبيت موديولات إضافية للمحاسبة أو المبيعات أو غيرها.

## أنواع التقارير الأربعة

يوفر الموديول أربعة أنواع من التقارير:

### 1. تقرير حركات المخزون (By Transfers)
يعرض جميع حركات النقل داخل المخزون خلال فترة زمنية محددة. يشمل تفاصيل كل عملية نقل مثل المنتج والكمية والمصدر والوجهة والتاريخ. مفيد لتتبع حركة المنتجات بين المستودعات والمواقع.

### 2. تقرير حسب الفئات (By Categories)
يعرض ملخص المخزون مجمّعاً حسب فئات المنتجات. يوضح كميات المنتجات المتوفرة في كل فئة مع إمكانية عرض التفاصيل. مفيد للحصول على نظرة عامة على توزيع المخزون.

### 3. تقرير حسب المستودعات (By Warehouse)
يعرض حالة المخزون في كل مستودع بشكل مفصل. يتضمن المنتجات المتوفرة وكمياتها في كل مستودع، مما يسهل مقارنة المخزون بين المستودعات المختلفة.

### 4. تقرير حسب المواقع (By Location)
يعرض حالة المخزون حسب المواقع (Locations) داخل المستودعات. هذا التقرير أكثر تفصيلاً من تقرير المستودعات ويعرض المخزون على مستوى الرف أو المنطقة داخل المستودع.

## التقنيات المستخدمة

### الواجهة الأمامية: مكون OWL
يستخدم الموديول مكون OWL (Odoo Web Library) لبناء واجهة المستخدم التفاعلية. مكون OWL هو إطار عمل JavaScript خاص بأودو لبناء واجهات ويب تفاعلية، وهو يعتمد على مفهوم المكونات القابلة لإعادة الاستخدام. يوفر المكون:
- اختيار نوع التقرير
- تحديد الفترة الزمنية
- اختيار معايير التصفية
- عرض النتائج في جدول تفاعلي
- أزرار التصدير (PDF / XLSX)

### استعلامات SQL خام
يستخدم الموديول استعلامات SQL خام (Raw SQL Queries) بدلاً من ORM الخاص بأودو. هذا الاختيار متعمد لتحقيق:
- **أداء أعلى**: استعلامات SQL المباشرة أسرع بكثير من ORM مع كميات كبيرة من البيانات
- **مرونة أكبر**: إمكانية كتابة استعلامات معقدة مع JOIN و GROUP BY والتجميعات
- **تحكم دقيق**: التحكم الكامل في استخراج البيانات المطلوبة

### التصدير
يدعم الموديول تصدير التقارير بتنسيقين:
- **PDF**: باستخدام محرك التقارير الخاص بأودو (QWeb)
- **XLSX**: باستخدام مكتبة Python المناسبة لإنشاء ملفات Excel

## كيف يعمل الموديول خطوة بخطوة

1. **فتح الموديول**: ينقر المستخدم على قائمة التقارير ويختار "تقارير المخزون"
2. **اختيار نوع التقرير**: يظهر مكون OWL الذي يعرض الأنواع الأربعة للتقارير
3. **تحديد المعايير**: يحدد المستخدم الفترة الزمنية ونوع التقرير وأي فلاتر إضافية (مستودع، فئة، منتج)
4. **تشغيل التقرير**: عند النقر على زر "تشغيل"، يتم إرسال المعايير إلى الخادم
5. **تنفيذ الاستعلام**: ينفذ الخادم استعلام SQL المخصص لاستخراج البيانات
6. **عرض النتائج**: تُعرض النتائج في جدول تفاعلي في مكون OWL
7. **التصدير**: يمكن للمستخدم تصدير النتائج كـ PDF أو XLSX

## ملاحظات ومشاكل محتملة

### نقاط القوة:
- **أداء عالٍ**: استخدام SQL خام يضمن سرعة في استخراج البيانات
- **واجهة حديثة**: استخدام OWL يوفر تجربة مستخدم حديثة وتفاعلية
- **مرونة**: أربعة أنواع من التقارير تغطي معظم احتياجات إدارة المخزون
- **تصدير متعدد**: دعم PDF و XLSX يلبي مختلف احتياجات المستخدمين
- **خفيف**: اعتماد على موديول واحد فقط

### مشاكل محتملة:
- **SQL Injection**: استخدام SQL خام دون معالجة مدخلات المستخدم بشكل صحيح قد يعرض النظام لخطر حقن SQL. يجب التأكد من استخدام المعلمات المعلقة (Parameterized Queries) وليس دمج السلاسل النصية مباشرة.
- **صعوبة الصيانة**: استعلامات SQL المعقدة أصعب في الصيانة مقارنة بـ ORM
- **التوافقية**: استعلامات SQL قد تحتاج إلى تعديل عند تغيير هيكل قاعدة البيانات في إصدارات أودو الأحدث
- **عدم استخدام ORM**: تجاوز ORM يعني فقدان بعض مزايا أودو مثل التخزين المؤقت (Cache) وقواعد الأمان التلقائية
- **الترجمة**: النتائج من SQL خام قد لا تكون مترجمة تلقائياً مثل نتائج ORM
- **غياب ملف الأمان**: قد يحتاج الموديول إلى قواعد أمان لتحديد من يمكنه مشاهدة التقارير وتصديرها
